The Linear Visualiser represents the Set of Bars, Particles and Particle Connectors that can be drawn on a straight line.

A Bar or a Particle is referred to as a `Primitive`.
A Primitive resides in a 'Fragment' (this is different from the Fragment in a Vertex / Fragment Shader), and has properties that define its size and appearance

A Fragment is the division of the total Window View into different 'Columns'. This serves as the housing space for the Primitives.
Each Fragment has a width that must be a constant throughout the current Frame of the Shader Program, and is represented by 'gap'.

Although both types of Primitives have a child structure that represents the Fragment, they're the same. They're supplied so for ease of reference. 

Window View -> divided into Fragments that have a width;
Fragment -> Houses Bars and Particles

If a Primitive's width exceeds that of the Fragment, then the Primitive appears as if it's been clipped or cut-off. This is intended, as no two Primitives from different Fragments can overlap.
This is because the Shader's logic divides the screen in different sections (Fragments) and treats them independently.

Working:

Linear and Angular work in similar ways. In the common configuration .glsl file, various variables and functions have been laid out that are essential for the Shader to Compile.

The variables primarily define the fragmentWidth of the Fragment, the vertical directions of the Primitives (Up, Down, or both), type(s) of Primitive to display (Bar, Particle, or both), and attributes for the Glow Post-Processing Effect
The functions serve as concrete stages in the processing of the Shader, and hence allow the specification of different values that affect the Primitives' Visuals.
